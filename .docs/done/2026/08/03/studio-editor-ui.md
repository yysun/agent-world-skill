# Agent World Studio Editor UI -- Completion

## Summary

- Delivered the Design surface of Agent World Studio: a React Flow canvas rendering the workflow as a graph (solid routing arrows, dashed `requires` arrows, entry marking, per-node agent/role/instruction preview), property panels for the world, nodes, and agents, a CodeMirror prompt editor, a read-only raw-JSON view, ELK.js automatic layout, and full save/validation/conflict handling -- all against the existing, unmodified Studio server.
- Graph editing is referentially safe by construction: `src/studio/client/workflow/mutate.ts` clones and patches the whole world document for every edit, so deleting a node strips it from every routing edge and every other node's `requires`, deleting an agent is refused (not cascaded) while any node still references it, and renaming a node or agent rewrites every reference including the workflow entry -- all covered by 20 automated unit tests with no browser.
- Saving, validation feedback, and external-change conflict handling are implemented in `src/studio/client/state/`: a rejected save never reports success or clears unsaved edits; validation errors are surfaced against the specific node, edge, agent, or field they name (not just logged); a world already invalid on disk surfaces its errors on load; and a file changed outside Studio reloads silently when there are no unsaved edits or offers Reload/Compare/Keep-Studio-Version when there are.
- Layout (node positions, viewport) persists only through the server's separate layout file and never touches the world document; automatic layout runs only on an explicit user action.
- Two client-code bugs were found and fixed during independent code review (see Notes), and one real architectural gap in the event-stream reconnect story was found and resolved during independent verification (see Notes).
- Two genuine, pre-existing constraints of the already-shipped Studio server were discovered during implementation and are documented rather than papered over: creating a brand-new agent's prompt file from a truly empty project cannot complete through the client alone (a chicken-and-egg dependency between the prompt-write and world-save endpoints), and a full server process restart cannot be recovered by the client alone (the server mints a fresh session token per launch). Both now fail or degrade visibly and clearly rather than silently.
- Updated `README.md`'s "Agent World Studio" section with a new "### The Design surface" subsection describing what the editor does and both documented constraints.

- VR (verification): ran twice on independent subagents building a REQ acceptance-criteria evidence matrix. This was resolved with a real forced-restart test using a token-pinned standalone harness (proving transient-drop reconnection genuinely works end-to-end) plus a new `session-expired` UI state for the unrecoverable-restart case, verified live against the real server. REQ, the E2E spec, and README were corrected to state this transient-vs-restart distinction precisely. The second VR pass confirmed "VR passed: all acceptance criteria complete"; all 33 REQ acceptance-criteria checkboxes are now checked with evidence.
- ET: every scenario in `.docs/tests/test-studio-editor-ui.md` was executed against running Studio instances across implementation and both review rounds using real browser automation (add/delete/rename node and agent, connect/disconnect edges via a custom canvas control, confirmation and cancel flows, blocked agent deletion, identifier validation, prompt editing round-trip, raw JSON view, automatic layout, manual-position persistence across a real process restart, rejected-save and already-invalid-on-load validation surfacing, silent reload, three-way conflict prompt with a working Compare diff, Studio's-own-save raising no conflict, and both the transient-drop and server-restart reconnect scenarios).

## Notes

- **Real bug found outside review, during ET**: the original "create first node and agent" flow tried to auto-create the new agent's prompt file via a best-effort `PUT /api/prompts/:agentId` call immediately after creating the node in memory. This always 404s: the endpoint resolves the agent from the world already saved on disk, not the client's pending document, and there is no server-side capability to create that file before the agent is saved -- while saving itself requires the prompt file to already exist. Removed the ineffective scaffold call; the create-node flow still works, and the resulting rejected save now surfaces a clear, specific error (the missing prompt path) instead of a silent failed side-effect. Documented as a known constraint in REQ Constraints, the plan's Rollback/Risk, and README, since it is a real limitation of the already-shipped server that this story is not permitted to change.
- **Reconnect scope was corrected, not weakened**: the original REQ wording ("reconnects... after the connection drops") was ambiguous between a transient drop and a full restart. The implementation now genuinely satisfies the transient case (proven with a real kill-and-restart test against a session-pinned harness) and handles the restart case honestly with a clear, actionable message rather than silently hanging or falsely claiming recovery. This required a client-only fix (a `session-expired` status distinguished via `EventSource`'s `readyState`); no server change was made or needed.
- **Scope discipline held**: no server file was touched at any point (confirmed via `git status`/`git diff` before each review); every edit is under `src/studio/client/`, `tests/studio/`, plus `package.json`/`package-lock.json` (new dependencies: `@xyflow/react`, `elkjs`, `codemirror`, `@codemirror/lang-markdown`, `@codemirror/lang-json`, `@codemirror/state`) and doc updates.
- No unrelated or pre-existing test failures; all 87 pre-existing suites pass unchanged throughout.
- Committed (`feat: add Agent World Studio workflow editor (Design surface)`), scoped to exactly this story's files (docs, README, `package.json`/`package-lock.json`, `src/studio/client/`, the built `skills/agent-world/studio/dist/` assets, and the three new test files).
