# Agent World Studio Server -- Completion

## Summary

- Delivered the Agent World Studio server: a loopback-only HTTP + Server-Sent Events service that resolves an Agent World project, reads/validates/atomically-saves `.agent-world/world.json`, reads/writes prompt files, watches for file changes, and pushes workspace events to connected clients.
- Studio never selects an agent, calls a model, executes a host action, or starts/stops/continues a run. It never invokes the router except through `loadConfig`, reached only via the new `Validator`; the ownership boundary is asserted by an automated test, not left to convention.
- Added the build toolchain (`package.json`, `tsconfig.json`, `vite.config.ts`, `scripts/build-server.mjs`) that compiles `src/studio/**` into committed artifacts inside `skills/agent-world/` (`scripts/agent-world-studio.js`, `studio/dist/`), so the skill needs no `npm install` or build step at run time.
- Shipped a minimal React client shell (`src/studio/client/`) that completes the token handshake, loads workspace metadata, and shows live event-stream connection status -- no canvas, property panel, or run/stop/continue affordance (that's the editor story).
- Security: loopback-only binding, session-cookie handshake that drops the token from the address bar, path-traversal/symlink-escape rejection for every filesystem-touching endpoint (including a gap found and closed during code review -- see Notes), and schema+graph validation before any write.
- Updated `README.md` and `skills/agent-world/SKILL.md` with the Studio launch command, implemented endpoints, and the layout-file separation.

## Notes

- **REQ acceptance criterion not yet checked**: "The built artifacts are committed and are not excluded by version control ignore rules." They are confirmed not-ignored, but nothing from this story has been `git commit`-ed. Per this repository's standing rule to never commit without an explicit request, that step was deliberately left for the user to authorize. Say the word and I'll run GC (stage the story's files and commit) -- this REQ box should be re-checked once that lands.
- **Two real bugs found and fixed during implementation** (not review): (1) `validator.ts`'s Ajv error extraction originally read `.errors` off the `Ajv` instance instead of the compiled `ValidateFunction`, which Ajv never populates that way -- every schema-invalid save silently succeeded until this was caught by manual testing and fixed. (2) `cli.ts`'s shutdown could hang on a lingering keep-alive SSE socket because `server.close()` alone waits for existing connections to end on their own -- fixed by calling `server.closeAllConnections()` after ending every SSE response, cutting the Studio test suite's runtime from ~11.3s to ~4.3s.
- **One security gap found and fixed during CR**: the dedicated prompt endpoints always ran `resolveInsideRoots` on `promptPath`, but the whole-world `PUT /api/world` / `POST /api/validate` path handed `agents.*.promptPath` straight to the router's `loadConfig`, which resolves it with a plain `path.resolve` and no containment check -- an absolute or `../`-escaping `promptPath` could reach a durably-written `world.json` uncaught. Fixed by checking every agent's `promptPath` with the same `resolveInsideRoots` before validation in both `saveWorld` and `validateCandidate`; two regression tests added and passing. A CR reviewer also flagged a very narrow non-blocking follow-up: `readPrompt` only special-cases `ENOENT` on read failure, so a different `fs` error (e.g. `EACCES`) would still surface the raw Node error message. Left as optional future hardening, not required by the REQ.
- **Deferred by design, not oversight**: the plan explicitly defers watching `.agent-world/runs/**` (no run-observation story exists yet to consume those events) and does not force a build-freshness check before commit (flagged as a release-packaging follow-up, out of this REQ's scope).
- No unrelated or pre-existing test failures; the 57 pre-existing router/eval suites pass unchanged throughout.
