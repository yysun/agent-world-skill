# JSON World Config Requirement

## Requirement

Agent World must use `.agent-world/world.json` as the only supported world configuration file.

The configuration is generated by an LLM, so the format must be strict, easy to validate, and free of homemade parser behavior. YAML is no longer supported. The router must load JSON with native `JSON.parse`; it must not keep a custom YAML parser as a compatibility path.

Agent prompts must live in separate prompt files referenced by the JSON config. This keeps the world graph machine-readable and keeps long prompt text readable in Markdown files.

## Acceptance Criteria

- The router defaults to `.agent-world/world.json`.
- `AGENT_WORLD_CONFIG` may still override the config path, but the loaded file must be JSON.
- The custom YAML parser is removed from the router.
- Sample and generated worlds use `promptPath` entries instead of inline `systemPrompt` blocks.
- A JSON Schema is checked in and referenced by generated `world.json` files.
- Tests create `world.json` and prompt files under `.agent-world/`.
- Documentation names `world.json`, not `agent-world.yaml`.
- No YAML compatibility behavior remains in code, docs, or examples.

## Non-Goals

- Do not add `js-yaml` or any npm dependency.
- Do not support both YAML and JSON.
- Do not redesign the Agent World state or handoff protocol.
